# ПРОТОКОЛ: БАРАБАН — Telegram Mini App бот

Бот для клубных розыгрышей в духе «русской рулетки»: создание битв, живой стол
с пистолетом, пиксельный интерфейс прямо внутри Telegram.

## Стек
- **Node.js + grammY** — сам бот (long polling)
- **Express** — раздаёт Mini App и REST API
- **better-sqlite3** — хранилище (один файл `data.sqlite`, ничего дополнительно поднимать не нужно)
- Фронтенд — обычный HTML/CSS/JS (без сборки), лежит в `public/`

## 1. Получить токен бота
1. В Telegram открой **@BotFather**.
2. `/newbot` → придумай имя и username (должен заканчиваться на `bot`).
3. Скопируй токен вида `123456789:AA...`.

## 2. Настроить .env
```
cp .env.example .env
```
Впиши `BOT_TOKEN`. `PUBLIC_URL` пока можно оставить пустым — заполнишь после деплоя.

## 3. Локальный запуск (без реального Telegram)
```
npm install
npm start
```
Сервер поднимется на `http://localhost:3000`. Без `PUBLIC_URL` бот не стартует,
но API и веб-страницу можно открыть в браузере — авторизация в этом режиме
подменяется тестовым пользователем (см. `allowDevFallback` в `server/auth.js`).

## 4. Деплой на Render
1. Залей проект в GitHub-репозиторий.
2. На [render.com](https://render.com) → **New → Web Service** → подключи репозиторий.
3. Настройки:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free достаточно для теста.
4. В **Environment** добавь переменные:
   - `BOT_TOKEN` — токен из BotFather
   - `PUBLIC_URL` — сразу после первого деплоя Render покажет тебе адрес вида
     `https://roulette-bot-xxxx.onrender.com`. Впиши именно его сюда и передеплой сервис
     (Manual Deploy → Deploy latest commit), чтобы бот подхватил переменную.
5. Важно: `PUBLIC_URL` обязательно **https** — иначе Telegram откажется открывать Mini App.

## 5. Прописать Mini App в BotFather (чтобы кнопка "Menu" тоже открывала приложение)
1. В BotFather: `/mybots` → выбери бота → **Bot Settings → Menu Button → Configure Menu Button**.
2. Вставь тот же `PUBLIC_URL`.
3. Название кнопки, например: `Барабан`.

## 6. Проверка
Напиши своему боту `/start` — придёт кнопка **«🔫 Открыть барабан»**, она откроет
пиксельный интерфейс прямо внутри Telegram.

## Структура проекта
```
server/
  index.js   — точка входа: поднимает Express + бота вместе
  db.js      — схема SQLite
  auth.js    — проверка подписи Telegram initData (защита API)
  game.js    — вся игровая логика (барабан, ходы, места)
  routes.js  — REST API для Mini App
  bot.js     — команды /start и /play
public/
  index.html — сам интерфейс (3 вкладки, пиксельный стиль)
```

## Права доступа
- Создавать битвы может **только владелец** (Telegram ID `618124780`, зашит по умолчанию
  в `server/admin.js`; можно переопределить переменной окружения `OWNER_ID`) и те, кого
  он добавит через вкладку **«Админ»** в самом приложении (видна только владельцу).
- В админке доступ выдаётся по Telegram ID или `@username` — вписываешь и жмёшь «Добавить».
  Кнопка «Убрать доступ» отзывает право в любой момент.
- Все остальные по-прежнему могут **присоединяться** к уже созданным битвам — ограничение
  касается только создания новых.
- `/start` отвечает по-разному в зависимости от того, кто пишет: владельцу, тем у кого
  есть доступ, и всем остальным.

## Важные правила игры (уже зашиты в `game.js`)
- Мин. игроков в битве — **2**, мин. холостых патронов — **10**.
- Боевых патронов всегда столько же, сколько реально зашедших игроков.
- Победителей должно быть меньше, чем макс. игроков.
- Стрельба в себя + холостой → тот же игрок стреляет снова (в себя или в другого).
- Стрельба в себя + боевой → игрок выбывает, ход — случайному живому игроку.
- Стрельба в другого — цель выбирается случайно среди живых (не сам стрелок);
  холостой → ход переходит к тому, в кого стреляли; боевой → тот выбывает,
  ход — случайному живому игроку.
- Игра всегда доигрывается до последнего выжившего. Место игрока = количество
  живых игроков в момент его выбывания. Топ-N мест (по полю «победителей»)
  считаются победителями и получают приз.

## Что стоит доработать перед реальным запуском
- **Выдача приза** сейчас не автоматизирована — после `finished` статуса
  посмотри победителей в API/интерфейсе и выдай приз вручную (или подключи
  свою логику, например отправку сообщения победителям через `bot.api.sendMessage`).
- **Диск на Render Free** не постоянный при пересоздании сервиса — если это
  критично, подключи Render Disk (платно) или вынеси БД на Postgres.
- Сейчас нет модерации призов/анти-абуза (например, лимит на число битв от
  одного пользователя) — добавь при необходимости.
